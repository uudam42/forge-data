# Forge Data

**面向机器人与物理 AI 的生产级多模态传感器数据处理平台。**

[English README](README.md) · [完整技术文档](docs/DETAILED_GUIDE.md)

从原始传感器文件到可复现、可追溯血缘的机器学习就绪数据集，共 10 个可独立测试的阶段，
并由统一的元数据治理层贯穿始终。

```
状态：10/10 阶段全部完成 · 878 个测试通过 · FastAPI + Pydantic v2 + SQLite
```

---

## 为什么做这个

机器人与物理 AI 团队产生的多传感器时间序列数据（IMU、GPS 等）往往很"脏"，在真正可用于训练之前
要经历漫长的流程：安全接入、模式校验、完整性检查、单位归一化、多流时钟同步、清洗过滤、特征工程、
数据集级质量控制、打包为带版本号的训练/验证/测试集——而且事后仍然要能回答一个问题：
"这份数据包到底从哪来的，我能不能复现它？"

**Forge Data 把这整条链路实现为一个连贯、逐步构建的平台**——每个阶段都是边界清晰、可独立测试的
服务；没有一处是笔记本脚本；每个产物都是不可变、带校验和、可追溯到原始来源的。

## 数据流水线

```
 原始上传            模式          完整性          单位            多流             清洗过滤        特征              数据集             版本化
(IMU / GPS)   -->    校验     -->  检查      -->   归一化    -->    同步        -->                提取     -->    质控        -->    打包      --+
  第 1 步            第 2 步       第 3 步          第 4 步          第 5 步          第 6 步          第 7 步          第 8 步          第 9 步     |
                                                                                                                                                   v
                                            +----------------------------------------------------------------------------------------------------+
                                            |
                                            v
                          第 10 步 — 元数据目录、全局血缘与数据集注册中心（对以上所有产物建立索引，而非另一处理阶段）
```

每个阶段都会写入一个不可变、带校验和的产物 + 清单（manifest），存放在各自独立的存储目录中。
第 10 步从不改写、重跑或修复任何上游产物——它只负责读取、建立索引和验证。

| # | 阶段 | 作用 |
|---|---|---|
| 1 | **数据接入** | 不可变原始上传，流式 SHA-256 校验，禁止原地覆盖 |
| 2 | **模式校验** | 逐条记录的模式一致性检查（IMU / GPS），结构化错误报告 |
| 3 | **完整性检查** | 超越模式形状的深层语义/范围/一致性检查 |
| 4 | **归一化** | 统一单位与时间戳，按模式可插拔的归一化配置 |
| 5 | **多流同步** | 将时钟独立漂移的多个数据流（IMU + GPS 等）对齐到同一时间轴 |
| 6 | **清洗过滤** | 确定性过滤、去重、脱敏策略 |
| 7 | **特征提取** | 确定性时间窗口切分与手工特征生成 |
| 8 | **数据集质控** | 对整份转换后数据集的分布/覆盖率/漂移检查 |
| 9 | **版本化打包** | 防泄漏、按组切分的训练/验证/测试集，框架无关导出 |
| 10 | **元数据与血缘** | 跨阶段有向无环图、数据集注册中心、不可变语义化版本、可复现性指纹 |

## 工程设计原则

- **一律不可变** ——任何变化都产生新 ID，绝不原地修改任何产物。
- **文件系统是唯一的真相来源** ——SQLite（仅在第 10 步引入）只是可重建的索引，绝非记录本身。
- **只报告问题，绝不静默修复** ——校验、质控、血缘验证只汇报问题，不做任何自动修补。
- **处处确定性** ——切分、指纹计算、特征生成均由种子驱动、可复现，绝非默认随机。
- **每个阶段均可独立测试** ——878 个测试用例，各阶段测试互不依赖运行时状态。

## 快速开始

```bash
git clone https://github.com/uudam42/forge-data.git
cd forge-data
python3 -m venv .venv && source .venv/bin/activate
pip install -e ".[dev]"

uvicorn app.main:app --reload   # http://localhost:8000
pytest                          # 878 个测试
```

最简单的端到端体验（完整流程见[完整技术文档](docs/DETAILED_GUIDE.md)）：

```bash
curl -X POST http://localhost:8000/api/v1/ingestion/upload \
  -F "file=@imu.csv" -F "customer_id=demo" -F "device_id=imu_001"
# -> { "ingestion_id": "ing_...", "status": "stored", ... }

curl -X POST http://localhost:8000/api/v1/catalog/rebuild   # 对目前已产生的一切建立索引
curl http://localhost:8000/api/v1/catalog/health            # -> { "status": "healthy", ... }
```

## 技术栈

Python 3.12+ · FastAPI · Pydantic v2 · pytest · 标准库 `sqlite3`（无 ORM）· 本地文件系统存储
（可插拔——存储抽象层已为后续接入 S3/GCS/Azure Blob 做好设计）。

## 项目结构

```
app/
    ingestion/ validation/ integrity/ normalization/    第 1-4 步
    synchronization/ cleaning/ transformation/            第 5-7 步
    qc/ packaging/                                        第 8-9 步
    catalog/                                               第 10 步 —— 索引、血缘、验证、数据集注册中心
    storage/         各阶段的不可变产物存储 + SQLite 元数据存储
    api/routes/       轻量 HTTP 层 —— 每个阶段一个路由模块
tests/                878 个测试，每个阶段至少一个测试文件
schemas/              内置的 IMU / GPS 模式定义
docs/DETAILED_GUIDE.md   完整技术参考（架构、API 表、错误码、MVP 限制说明）
```
